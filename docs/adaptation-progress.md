# 差异补齐进度

2026-10-08，当前默认配置：厂长、干饭、一碗、蔬菜、动漫巴士、急救教学、奥特影视。原参考 Cat 目录与本项目已有条目均先去重，没有重复添加。

这些是独立站点，不与已有 Cat 仓库合并，也不会自动导入 Android 订阅。上传本项目后使用生成的 `.js.md5` 新建仓库即可。

本轮实现了两个缺失条目：

- 蔬菜：复用 AppGet 协议，新增文本发布页的动态接口发现，避免把临时 IP 固化在配置中；首页没有推荐时读取首个分类。
- 动漫巴士：独立 HTML 适配器，包含分类分页、搜索、集数列表、iframe 参数读取、播放器 `/api/parse` 请求和 `hls_rewrite` 地址处理。不执行播放器网页里的混淆脚本。

后续尚需协议适配的重点：农民、光盘、潮流、行动/再来、奥特、比特、糯米等。网盘聚合及搜索站还需分享解析与个人账号接口；P2P/磁力站还需播放引擎，不能仅补站名。

第三批：

- 急救教学：饭太硬和肥猫都有，统一为一个条目。八类栏目、分页、栏目内标题搜索、详情和播放已实现；搜索范围仅限急救栏目，区别于全站医学搜索。Docker 检出 720p H.264 和 AAC。
- 奥特影视：对应饭太硬缺失站点。根据当前官网 HTML 独立编写，支持五类、多线路与 base64 媒体地址；搜索动态读取表单，不再固定旧 PHP 文件名。源站要求验证时返回明确提示，实际视频仍待验证。
- 农民影视：公开配置入口根页面返回404内容，尚未据此添加不可用模块。

奥特条目从上面的“待适配”移到“已实现、部分验证”。其余待适配项目保持原状态。自本批开始只提供变更源码增量包，不包含 dist、依赖或未改动文件。

已测试但上游不可用的条目和实际播放验证边界见 [验证记录](verification.md)。本轮不声称把三个 Android 订阅的全部站点补齐。

## 第四批补齐

- 潮流：独立 AppRJ 适配器，支持签名请求、筛选、搜索、详情和多解析入口；Docker 取得10分类、首页12条、搜索2条、详情3线路及HLS，ffprobe尚未通过。
- 光盘：在 AppGet 中独立区分 Qiji 协议命名空间和初始化版本，使用 JSON 请求体；Docker 取得9分类、首页30条、详情2线路，并检出1920×1080 H.264和AAC。原搜索接口HTTP404，仍未解决。
- 行动/再来：发布页可访问，原协议包含 Protobuf、RSA/AES及多重签名，尚未完成独立实现。
- 荐影：公开列表可访问，详情返回验证页面；未添加只能列目录的空适配器。
- 比特：已定位现行官网及公开 WASM 播放入口，尚未实现播放协议。

当前默认9站；全部原始150条目的去重与实施状态见 adaptation-status.md / references/adaptation-status.json。50个原条目仅有参考Cat候选，不算作本项目已适配。其余待实现条目继续保留，不能声称全部完成。
